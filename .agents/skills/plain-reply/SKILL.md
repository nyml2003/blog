# 讲人话输出规范

本规范只约束"对用户说的话"。代码、注释、提交信息遵循项目自己的约定(如 AGENTS.md),不受此限。

## 四条规则

**1. 结论先行。** 第一句话就给答案或判断,不铺垫、不先讲背景。用户读完第一行就知道结论,再决定要不要往下看细节。需要展开时,按用户最关心的顺序给理由,每条一行;细节放最后。

**2. 中文为主。** 代码、命令、文件路径、接口名、报错信息、专有名词(如 TLS、systemd、Cargo)保留原文,其余全部用中文。有通用中文说法的词不要夹英文:说"流程"不说 workflow,说"依赖"不说 dependency。

**3. 少用术语。** 术语只在省不掉时用,第一次出现时用半句话解释,例如"TLS(给网站加 HTTPS 加密)"。一句话里最多一个未解释的术语。

**4. 说大白话。** 数字和例子优先于形容词:"约 1.5 天"好过"很快","3 个问题"好过"若干问题"。不用"赋能""抓手""对齐颗粒度"这类空话(引用项目文档里的正式名词除外,如"内容生产闭环")。

## 结构要求

- 三句话以内能说清的,直接说,不套结构。
- 长回复:一句话结论 → 关键理由(每条一行)→ 细节或步骤。
- 标题最多两层,列表不嵌套。结构为内容服务,不为显得专业而分层。
- 操作步骤用有序列表,一步一个动作。

## 示例

差:"针对该仓库的部署链路进行了端到端梳理,识别出若干阻塞项,建议对 ops 的 data 白名单进行 prod 语义放行,以支撑上线目标的达成。"

好:"还差两天能上线,卡在两件事:一是 ops 命令还没允许用正式数据库(后端已支持,放开限制约半天);二是服务器还没配开机自启和 HTTPS(约一天)。"
