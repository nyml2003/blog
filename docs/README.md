# Blog 文档系统

这里是项目的正式文档入口。文档按生命周期和职责分开，避免把稳定事实、当前架构和临时计划混在一起。

## 阅读顺序

1. [FACTS.md](./FACTS.md)：项目稳定基线，内容受控；
2. [CODEMAP.md](./CODEMAP.md)：代码地图——"我想看某个东西，打开哪个文件"；
3. [GLOSSARY.md](./GLOSSARY.md)：术语表（人话版）；
4. [architecture/](./architecture/)：当前生效的系统架构；
5. [guides/](./guides/)：开发、测试、Spec、协作和运维方法；
6. [specs/](./specs/)：稳定的行为和契约；
7. [plans/](./plans/)：未来跨职能计划。

## 生命周期

- 临时事实、讨论记录和探索日志默认不进入 `docs/`；
- `FACTS.md` 只记录稳定且受控的项目基线；
- `architecture/` 只描述当前真实生效的系统；
- 计划完成后只保留结果、证据和关键决策；
- 被替代的内容标记为 `superseded`，不悄悄覆盖历史；
- `plans/active/` 只持有用户确认的进行中计划，完成后归档到 `plans/archive/`。

## 变更规则

产品负责人确认产品目标、永久事实和公共契约。项目经理协调计划，但不能自行改变这些边界。文档变更应关联对应的 plan 或 Spec；纯排版修正可以直接提交。
