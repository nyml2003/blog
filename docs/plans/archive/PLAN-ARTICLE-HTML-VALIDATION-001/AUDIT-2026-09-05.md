# 存量正文只读审计（候选 Profile 前）

本记录是对工作区 `blog.db` 的只读形态审计，不是新 Profile 下的合规结论。执行时没有写入数据库，也没有修改正文。

## 可重复执行

在项目根目录运行：

```sh
sqlite3 -readonly -header -csv blog.db \
  "select id,status,length(cast(content_html as blob)) as bytes,content_html from articles order by id;"
```

随后对 `content_html` 做逐字符 parser 审计；在 Profile 决策完成前，只统计标签、属性和高风险形态，不把浏览器容错结果当作合法性判断。

## 当前结果

- 文章总数：102；已发布：100；草稿：2。
- 观察到的元素只有 `h2`、`p`。
- 观察到的属性集合为空。
- 当前抽样规则未发现 `script`、事件属性、`style`、`javascript:`、`iframe` 或 `form` 形态。
- 原记录误把 SQLite `length(text)` 的字符数记为字节数（草稿 3/10、已发布 85）；2026-09-06 修正为 `length(cast(content_html as blob))`，实际最长正文为 201 UTF-8 字节。精确 v1 检查和重建证据另见结果记录。

这些结果只能说明当前数据库样本的表面形态，不能证明它们满足尚未确认的实体、URL、嵌套、资源上限或 source span 规则。Profile version 确认后必须用共享 Rust parser 重新执行，并输出稳定的 `article_id / diagnostic_code / profile_version` 清单。

## 已确认的产品约束

- 正文第一期不支持图片；`img` 及其 `src` 属性进入禁止集合。未来若开放图片，必须单独修订 Profile version、URL 策略和渲染验收，不通过隐式放行实现。
- 正文完全禁止 `class` 属性。
- 允许 `http`/`https` 链接，且必须显式写出 `target="_blank"` 与 `rel="noopener noreferrer"`；校验器不自动补写。
- 当前数据库内容是测试数据，按 v1 上线前删除并以合法 fixture 重建；不做自动迁移或自动修复。

## 候选修复与回滚策略（待产品确认）

1. 先用 SQLite `.backup` 备份数据库（包含 WAL 已提交数据）并记录校验和；审计工具只读副本。
2. 先按确认后的 Profile 生成违规清单，不自动改写正文。
3. 发布边界接入服务端校验后，历史违规文章按确认策略处理：修复后再发布、显式隔离，或继续展示但禁止重新发布。
4. 任何迁移都必须在备份和副本验证通过后单独授权；回滚以备份文件恢复为准，不能依赖正文“自动修复”。
