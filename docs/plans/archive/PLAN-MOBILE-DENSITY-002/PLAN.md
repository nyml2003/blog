# C Mobile 信息密度优化 002

## 目标

在 `PLAN-MOBILE-DENSITY-001` 完成并获得真实验收证据后，先以视觉和产品视角盘点当前 C Mobile 的页面、元素、信息层级和交互摩擦，再以 C Mobile 详情页为主线，优化正文进入路径和文章 HTML 渲染 CSS 的移动端信息密度。推荐页和文章库本轮只作为审计对照，不默认进入实现。

## 成功标准

- 有真实的 001 验收基线、问题清单和移动端视口证据；
- 有当前移动端页面/元素清单，以及每个页面的视觉问题和候选改进方向；
- 候选改进按影响、成本、风险和依赖排序，形成后续迭代建议；
- 识别并修复详情页进入正文和连续阅读中的明显信息摩擦；
- 详情页标题区、元数据、正文入口和返回路径的信息优先级经过实际数据验证；
- 文章 HTML 正文在 Mobile 下的标题、段落、列表、代码、引用、表格和图片渲染有明确密度规则；
- 推荐页和文章库完成审计记录，但非详情页问题不会自动扩大为本轮实现范围；
- 优化后仍满足触控、可读性、无横向滚动、布局稳定和页面隔离约束；
- 变化可以通过 `SPEC-*` 场景和前后对比证据回溯。

## 非目标

- 不在 001 尚未验收时并行重做同一页面；
- 不以“更紧凑”为理由降低正文可读性或触控目标；
- 不修改 PC、B 端、领域模型、推荐算法或公共 API；
- 不引入新的全局状态、缓存或响应式合并方案；
- 不把本计划变成完整视觉换肤或新主题计划。

## 进入条件

- `PLAN-MOBILE-DENSITY-001` 已完成，或 PM 已确认其实现部分可作为稳定基线；
- 具有至少一个窄屏和一个常见手机视口的验收记录；
- 已记录真实文章数据下的空白、重复字段、筛选和返回路径问题。

## 优化方向

- 详情信息密度：标题、摘要、标签、时间和类型的取舍及重复消除；
- 正文进入路径：减少装饰性留白、重复返回和不必要的标题区层级；
- HTML 渲染 CSS：移动端正文宽度、字号、行高、标题间距、列表、代码、引用、表格和图片；
- 内容连续性：长标题、无摘要、长文和代码块不会造成异常跳跃或过度留白；
- 阅读导航：顶部返回和底部返回是否重复，长文是否需要后续独立能力；
- 状态占用：详情加载、错误和不可见状态不挤压主要阅读区域；
- 对照审计：记录推荐页和文章库问题，但只有与详情页共享的正文/主题问题才可纳入本轮实现。

## 当前页面盘点基线

### 推荐首页 `/m/`

- sticky 顶部品牌 Header；
- 页面眉题、主标题和说明文案；
- 推荐文章列表；
- 文章条目：类型锚点、标题、摘要、标签、更新时间；
- “浏览全部文章”主操作；
- 底部导航；
- 加载、错误和空结果状态。

### 文章库 `/m/articles/index.html`

- sticky 顶部品牌 Header；
- 页面眉题、主标题和总数说明；
- 筛选触发器及当前条件数量；
- 底部 Filter Panel：文章类型、主题/标签、创建时间、更新时间；
- Shelf 左侧分区索引及滚动定位；
- Shelf 分区标题和文章数量；
- 分区文章条目：标题、摘要、标签、更新时间；
- 底部导航；
- 加载、错误和空结果状态。

### 文章详情 `/m/articles/detail.html`

- 阅读 Header；
- 返回文章库/返回文章操作；
- 文章类型、标题、摘要、更新时间；
- 系统主题包裹的 HTML 正文；
- 文章底部返回入口和知识库标识；
- 加载和文章不可见/不存在状态。

### 002 候选提升路线

- 信息密度：标题、摘要、标签、时间和类型的取舍及重复消除；
- Filter：筛选入口可见性、已选条件表达、应用/清除路径和底部面板操作效率；
- Shelf：左侧索引是否值得占用固定宽度、分组是否帮助扫描、条目层级是否过深；
- 首页：推荐条目与“浏览全部文章”的首屏比例和主次关系；
- 详情：标题区、元数据和正文进入点的空间分配；
- 导航：顶部 Header、阅读返回和底部导航是否存在重复路径；
- 状态：加载、错误、空结果是否占用过多空间或缺乏恢复动作；
- 内容边界：长标题、无摘要、过多标签和日期格式的稳定呈现。

## 集成验收

1. 视觉审计先产出页面/元素清单、问题证据和候选改进方向。
2. 产品工作流将问题按频率、影响、实现成本和依赖排序，产出本轮 `SPEC-*` 和后续计划建议。
3. 视觉工作流只针对详情页和文章 HTML CSS 调整密度和交互，不进行无目标装饰改版。
4. 前端工作流保持 C Mobile 独立实现，完成详情页和正文渲染的前后对比。
5. 测试工作流验证正常、空、错、长内容和筛选状态，并确认 001 的行为没有回归。
6. PM 根据证据决定本轮完成、拆分为后续 003 计划或回退，不以主观“看起来更紧凑”作为唯一验收依据。

## 未决项

- 本轮首要问题由 001 的真实验收和用户反馈确定；
- 是否调整推荐页与归档页的页面合并关系，属于对照审计结果，默认延后；
- 是否引入更激进的分组、折叠或分页，待证明当前结构无法满足扫描目标后再决定。

## PM 执行默认

- 计划启动即进入 `in_progress`；各工作流按依赖逐项推进，不等待所有审计完成后才更新状态。
- 正式数据库只用于读取基线；长标题、长正文和复杂 HTML 使用临时数据库副本补充压力样本。
- 现有 `.article-body` 规则视为 Mobile 系统主题 wrapper，本轮只调整其移动端密度，不引入文章级 CSS 或新的内容协议。
- 当前已知 Biome 格式差异限定为机械清理项，修复后必须重新运行完整 `ops quality check`。
