## 已确认

### DECISION-001：统一 Field 与独立 Select 组合

- 用户选择统一的 `Field` 包住独立 `Select`。
- `Field` 属于原子之上的表单项组合层，负责标签与控件的组合和布局；`Select` 保持独立受控控件。
- 设置页不再通过 `<p><Label ... /></p>` 借用段落样式表达表单项布局。
- 本项修订首轮只由页面手动组合 `Label + Select` 的方案；不新增无关原子。
- Field 的关联职责见 DECISION-005；具体接入机制由前端按组件契约实施，说明与错误信息接口不在本轮范围。

### DECISION-002：选项与设置读写来自数据层

- 用户要求主题和字体读写经过 `common/data`，页面 UI 不耦合存储访问。
- 可选项也是数据；无论暂时来自代码常量还是将来后端下发，均不得直接写在页面 UI 中。
- Data / Client / Mobile 适配层的职责与首绘复用原则见 DECISION-008，Select 数据接口方向见 DECISION-003 / 004；组件不自行取数。

### DECISION-003：Select 变更回调返回选中值

- 用户认可 `Select` 使用 `onChange(value)`，直接向调用方返回选中的值。
- 原生 DOM change 事件与 `event.currentTarget.value` 的读取由 Select 内部处理，不要求页面操作 DOM 事件。
- Select 保持受控：当前值由调用方传入，变更通过回调通知；本项不引入组件取数或持久化职责。
- 本项是对首轮 Select 事件 Props 契约的明确修订方向，具体值类型随选项数据结构一同确定。讨论完成前不修改源码或归档契约。

### DECISION-004：Select 接收统一选项数据

- 用户认可 Select 的选项列表使用统一的 `{ value, label }` 结构：value 是稳定标识，label 是显示文本。
- 数据层提供选项列表，页面将列表传入 Select；原生 `<option>` 由 Select 内部生成，页面不手写选项节点或选项数据。
- 外部响应若采用其他结构，由 Client 层转换；Select 不感知数据来自代码常量还是后端，也不要求页面提供字段提取函数。
- 选项 value、受控当前值和 `onChange(value)` 使用一致的值类型；前端确定精确类型，本轮使用完整列表与合法默认值，不扩展空选项。
- 本项修订首轮以 content 传入原生 option 节点的方向，具体 Props 命名和实现随完整契约一同确定。

### DECISION-005：Field 统一管理标签与控件关联

- 用户认可由 Field 统一管理标签与内部控件的关联，页面不再分别给 Label 和 Select 重复维护同一 ID。
- 页面提供标签并组合独立控件；Field 负责建立可访问关联，保证点击标签能聚焦对应控件，辅助技术能识别控件名称。
- Select 保持可独立使用，独立场景仍须支持设置可访问名称。
- 本项确定关联职责，不预先选定 Context、render prop 或其他接入机制；具体 Props 与内部实现由前端按完整契约确定。

### DECISION-006：mobile-ui 分层目录与首个页面容器

- 用户认可 `atoms/`、`molecules/`、`containers/` 和 `styles/` 的目录分工。
- `atoms/` 保留独立控件；新增 `molecules/` 承载 Field 等稳定局部组合；新增 `containers/` 承载页面级结构与布局。
- 本轮先以设置页为用例增加 `PageContainer`，不提前铺开整套布局组件库。
- 容器层管理页面背景、内容宽度、留白、安全区和基础布局；保持纯 UI 职责，不取数、不读写设置、不包含设置页业务语义。
- 本项只确认目录和组件方向；随后确认的主题边界见 DECISION-007。
- 目录与组件已经纳入统一契约和实施写集，随本轮编码落实。

### DECISION-007：PageContainer 承载主题作用域

- 用户认可将主题作用域从各 atom 根提升到 mobile-ui 的 PageContainer。
- 容器背景、留白区域、Field 和内部控件整体承接颜色与字体设置，原子不再为实现主题而各自形成独立背景块；控件自身必要的语义表面仍由组件样式管理。
- 未迁移的旧页面保持原样，不因本项自动进行主题适配或页面迁移。
- 本项明确修订首轮 Plan / Spec 的 atom 根限定；主题值域、字体值域、存储键名和即时生效要求不变。
- PageContainer 仍为纯 UI，不读取存储或获取业务数据；设置的读取与应用通过外部数据和适配层衔接。
- 本项已纳入 Spec、组件契约、CSS 所有权和工作流写集，随本轮编码落实；验收状态单独记录。

### DECISION-008：设置数据的分层与首绘复用

- 用户认可沿用 Data / Client / Mobile 适配层 / 页面与 mobile-ui 的分工。
- `common/data` 提供通用存储与传输能力，处理实际读写和异常，不包含主题、字体等业务语义。
- `common/client` 提供主题与字体选项、当前设置的读取和保存能力；当前固定选项放在该层，将来可替换为后端数据来源，页面不感知来源变化。本轮不新增后端设置接口。
- Mobile 适配层连接 Client 与页面状态，将设置应用到主题载体，并协调首绘初始化。
- 页面与 mobile-ui 接收数据、展示内容并发出变更，不直接访问存储或定义选项列表。
- 首绘复用同一套读取与校验逻辑，不在 HTML 内联脚本中独立维护另一份存储键名、枚举或容错规则；具体同步装配方式在实现设计中确定。
- 本项修订首轮页面取得 localStorage、Mobile logic 直接读写以及 HTML 独立实现读取规则的方案，随本轮编码整改。

### DECISION-009：新页头与底部导航纳入设置页主题

- 用户确认设置页的页头和底部导航一并切换主题，并授权在 mobile-ui 下新做两个组件，目录位置由 PM 按分层确定。
- PM 将 `PageHeader` 和 `BottomNav` 放在 `mobile-ui/molecules/`，拟定文件为 `page-header.tsx`、`bottom-nav.tsx`，与 `field.tsx` 同层。二者属于原子组合出的完整局部 UI，具有明确的展示或导航语义。
- `mobile-ui/containers/page-container.tsx` 负责页面布局和主题边界，容纳页头、主体和底部导航；页面定位、安全区和内容避让由容器协调，组件自身管理内部布局与交互外观。
- PageHeader 的标题、品牌等展示内容，BottomNav 的导航项和当前选中项，由外部传入。mobile-ui 不内置博客路由表，不自行读取 location、设置或 Client，不反向导入 legacy 业务组件。
- 本轮设置页使用新组件，页头、主体和底部导航整体继承 PageContainer 主题。其他旧页面继续使用既有组件，不在本项中迁移。
- 这是用户批准的迭代方向与 PM 目录安排；编码已派发，不因本记录标记交付或验收完成。

## 实施整理项

- 本设置页保留现有字符串枚举和必有合法默认值，不扩展清空、搜索、多选或通用空列表能力。
